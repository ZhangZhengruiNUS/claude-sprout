## Current State

- Claude Sprout is a public GitHub repository at https://github.com/ZhangZhengruiNUS/claude-sprout.

- The primary surface is a transparent, frameless, always-on-top pet window. The full session panel is secondary and opens from the pet or tray.

## Known Blockers

- Direct NSIS/WiX tool downloads through the normal Tauri/PowerShell TLS stack can still fail in the Codex sandbox because SChannel cannot create TLS client credentials. Use npm run release:precache-tools to populate the local Tauri tool cache through Node HTTPS before installer builds.
- MSI bundling is optional and still depends on WiX being present in src-tauri\target\.tauri\WixTools314 or installed on PATH; npm run release:precache-tools now populates the local WiX cache without requiring winget or NetFx3.
- The release exe build works with npm run release:exe or npm run tauri -- build --no-bundle, and the NSIS installer build works while the verified local NSIS cache is present.

## Important Decisions

- Do not make the product a browser-style dashboard. The pet window is the first-class UI.
- Do not auto-approve Claude Code permission prompts.
- Keep prompts/outputs out of stored state by default.
- PowerShell hook writer is the default for Windows; Node hook writer remains a fallback.
- Imported Codex-compatible pet assets are copied into Claude Sprout app data; do not reference or distribute official Codex assets.
- Conversation preview is an explicit local opt-in. Default behavior stays metadata-only; when enabled, writers may store only a single truncated User/Claude transcript snippet in sessions/*.json and must not append prompt/output snippets to events/*.jsonl.
- Official Windows release artifacts are the standalone release exe and NSIS installer; MSI remains an optional maintainer build, not a required release artifact.
